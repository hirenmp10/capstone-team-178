### HS-1 — Uno watchdog detaches the arm during every normal pause; nothing on the Jetson feeds it while idle  
**CRITICAL** · hardware_safety · `jetson/robot_server.py:1300`

**Status: FIXED.** Keepalive thread `ServoDriver.start_keepalive` (`jetson/robot_server.py:965`) sends a one-byte `K` frame every 150 ms while idle (sketch `servo_bridge.ino:157`); `get_state` asks the bridge and reports `attached` (`robot_server.py:2032`). Tests: `tests/test_hardware_bridge.py::test_two_seconds_idle_stays_attached_with_keepalive`, `::test_without_keepalive_the_fake_watchdog_detaches` (negative control), `::test_keepalive_feeds_the_watchdog_with_k_frames`. Live proof 2026-09-24: fake lane with `--fake-watchdog-ms 500`, 84 `get_state` samples through see -> pick -> 2 s idle -> place, 0 with attached=false, no 'detached by the bridge' in the server log.

**Claim.** On the uno_serial path a P frame is sent only when a command writes (UnoSerialDriver._send_pulses, robot_server.py:699); RobotServer._loop (1300-1316) has no timer or keepalive. servo_bridge.ino:48 and :237-239 detach every servo after 500 ms without a frame, and the next P frame re-attaches with current_us = target_us (ino:146-151): an unlimited-speed, uncoordinated snap. Every normal idle gap in a pick exceeds 500 ms, so the arm goes limp mid-task, drops what it holds, then snaps back. RemoteController.hold_position (mfw/hardware/controller.py:214-216) is a no-op on the premise that the Jetson keeps pulsing the last target, which is false on the Uno path.

**Failure scenario.** Real pick, Uno driver: descent completes -> _settle_at sleeps 200 ms (WallClock.step, mfw/hardware/clock.py:120-121) -> primitives.py:721 observe() (get_frame round trip + NanoOWL, >= 500 ms) -> watchdog fires with the jaws 10 mm above the table beside the object; forearm and tool collapse onto it. close_gripper_blocking then sends one P frame: servos re-attach and snap from the collapsed pose to the grasp pose at full speed. After the lift, the verification observe (primitives.py:750-752) trips it again while the object is held: object dropped from 6 cm, arm collapses, Place's first chunk snaps it back up. Between commands the arm lies limp as long as the student is talking.

**Evidence.** Read the sketch watchdog and attach code; grep for keepalive/heartbeat/watchdog across mfw/, jetson/, scripts/ finds no periodic re-send (docs only). Read RobotServer._loop, UnoSerialDriver, RemoteController.hold_position/_settle_at, Pick steps 5-8, WallClock.step. Tests cannot see it: FakeDriver has no watchdog and the scripted detector answers instantly.

**Suggested fix.** Add a keepalive thread in RobotServer (or UnoSerialDriver) that re-sends the last pulses every ~200 ms while attached and not estopped; or raise WATCHDOG_MS only for the true stall case and document that a P frame is the heartbeat. Add a test with a fake Uno that enforces the 500 ms rule.

**Skeptic.** Re-read servo_bridge.ino: only P/T frames set last_frame_ms (line 168); the '?' query does not; loop() detaches after 500 ms (237-239); the next P frame re-attaches with current_us = target_us (146-151), so the slew limiter never applies to the re-attach jump. On the server side UnoSerialDriver only writes the wire inside _send_pulses/_send_detach (robot_server.py:699-704), RobotServer._loop (1300-1316) is a pure poll/dispatch loop with no timer, get_state/read_commanded never touch the serial port, and a repo-wide grep for keepalive/heartbeat/watchdog finds only the sketch and two doc mentions. RemoteController.hold_position (controller.py:214-216) is an explicit no-op that assumes the Jetson keeps pulsing. With max_joint_velocity 1.2 rad/s and the assistant single-threaded, every gap longer than 500 ms (observe round trip, the student speaking, the LLM/intent parse between 'pick' and 'place') detaches the arm; whether the post-lift observe() alone exceeds 500 ms depends on detector latency I could not measure, but the between-command gap on the voice path is seconds, so a held object is dropped and the arm slumps before every Place. Cannot be reproduced against FakeDriver (no watchdog), which is exactly why 696 passing tests do not see it.

**CRITICAL** · protocol_robustness · `jetson/robot_server.py:651`

**Status: FIXED.** Same keepalive as HS-1, plus: `get_state` reports the Uno's own `attached`, `bridge_q`, `bridge_gripper_width`; the first motion after any detach is one slow `T` frame (`ServoDriver.reattach`, `robot_server.py:899`); `FakeDriver(watchdog_ms=...)` / `--fake-watchdog-ms` model the Uno, and `run_assistant.py --fake-hardware` spawns the fake with it (`scripts/run_assistant.py:266`); RemoteArm warns when the servos detach without our estop (`mfw/hardware/remote_arm.py:291`); the controller stops a trajectory whose reply says `detached` (`mfw/hardware/controller.py:176`). Tests: `tests/test_hardware_bridge.py::test_cli_flag_builds_a_watchdog_fake`, `tests/test_hardware_motion_guards.py::test_a_detach_without_our_estop_is_surfaced`, `::test_fake_robot_server_is_spawned_with_the_uno_watchdog`, `::TestClampStopsTheMotion::test_a_detach_during_a_chunk_stops_the_motion`.

**Claim.** UnoSerialDriver sends a P frame only when a write happens (ServoDriver._emit, line 569); nothing on the Jetson re-sends frames while the arm is idle, but servo_bridge.ino detaches all five servos after 500 ms without a P/T frame (ino lines 48, 237). **Failure scenario.** Real Uno lane: 'pick up the marker' completes (last chunk shipped, gripper closed), the assistant returns to the robot> prompt or waits for the LLM. 500 ms later the Uno detaches -> forearm drops onto the table, marker falls out of the jaw. ## What looked right

- **[hardware_safety]** Straight joint-space homing from top-down grasps at r = 0.10-0.20 m on the placeholder geometry never dips a link below 10 mm above the table (experiment B), so the Jetson home endpoint is benign from ordinary grasp poses.
- **[hardware_safety]** float32 transport of waypoints exactly on a joint limit does not trip the Jetson clamp (experiment C: clamped flag stays False at both limit vectors).
- **[hardware_safety]** Chunk boundaries are safe for velocity: consecutive chunks do not overlap and the first sample of the next chunk is one planner dt (max 1.0 rad/s) away; the Uno slew limit (20 us/tick = about 1.75 rad/s on the placeholder map) and the server's 1.2 rad/s ceiling both sit above it.
- **[hardware_safety]** DTR reset on port open is handled: UnoSerialDriver waits 2 s and flushes; the sketch keeps servos detached until the first valid frame and writes the target before attach(), so there is no jerk to 1500 us at boot.
- **[hardware_safety]** The sketch's own clampUs runs before Servo.writeMicroseconds, so int8 overflow in the Arduino Servo library's min/max (if MIN_US is tightened above about 1052 us) cannot widen the effective range.
- **[hardware_safety]** PCA9685 detach uses the full-OFF bit correctly and the prescale gives 50 Hz; the server refuses to start a real driver without a calibration file.
- **[hardware_safety]** Gripper handling on a failed pick attempt is sane: the finally block only restores collision, the next attempt opens the jaws first, and memory never records a hold that verification did not confirm; jaw commands are clamped to the calibrated pulse span at both ends.
- **[geometry]** TCP frame consistency: PlanarKinematics.fk assembles its frame by calling build_grasp_pose itself, so its Y column is the closing axis by construction; numerically, IK->FK of TopDownGraspGenerator._frame poses for a radial jaw at pitches 90/75/60 reproduces the Y column to 1e-16, and the tangential case is pinned by test_fk_jaw_axis_equals_build_grasp_pose_y_for_a_top_down_grasp.
